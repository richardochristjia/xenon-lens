## Answer

**Verified facts.** Lavish is an active MIT-licensed local HTML review implementation. Agent CLI opens one file in browser chrome; sandboxed artifact SDK supports element/text annotations and artifact-authored structured input; browser queues feedback until explicit submission; server persists accepted batches; agent receives them through long polling and can return browser-visible replies. It also implements live reload/recovery, conversation history, attachments, diagram whiteboards, passive layout diagnostics, export, optional sharing, mobile review, and skill/hook/plugin discovery. These are Lavish capabilities and prior art, not Xenon Lens innovations.

Architecture is Node 22+ ESM CLI plus one local Express server, WebSocket browser events, HTTP agent poll, Chokidar file watching, JSON state and sidecars under `~/.lavish-axi`, browser chrome, and sandboxed artifact iframe with injected SDK. Sessions are keyed by canonical HTML file path. Public seams are documented CLI/structured output, `window.lavish`/`data-lavish-*` artifact conventions, skill/plugin packaging, and share-backend contract. Internal routes, WebSocket/postMessage shapes, state schema, and source modules are not versioned public APIs; npm exports a binary, not a reusable runtime library.

Lavish explicitly scopes itself to one person, one agent, and one local HTML file. Current sources do not provide Xenon Lens's multi-artifact Collaboration Session, Originating Agent entitlement/handoff, explicit Acceptance, or durable stable Target contract. Browser “take over” is tab ownership, not agent handoff. Artifact scripts can programmatically queue and send through `window.lavish`; current-load/source checks do not prove human activation, so Xenon's untrusted-artifact intent boundary needs separate validation.

Maintenance is vigorous but pre-stable: 215 commits and 71 release tags in about four months, current main CI passing on Ubuntu/macOS/Windows, frequent `0.1.x` releases, one dominant maintainer, outside contributions, and no compatibility policy found. Pinning and black-box upgrade tests are required. No explicit Chrome/Edge/Firefox support matrix was found.

README claims token efficiency from TOON output, long polling, and contextual disclosure. No quantitative token measurements, controlled benchmark, or raw token logs were found. Token savings remain an **unmeasured hypothesis**.

MIT text permits use, copying, modification, merging, publication, distribution, sublicensing, and sale, conditioned on preserving copyright and permission notice in copies/substantial portions. Bundled code/fonts retain MIT or SIL OFL obligations in `THIRD-PARTY-NOTICES.md`. No CLA, trademark policy, or separate branding grant was found; `ht-ml.app` is a separate third party. This records evidence, not legal advice.

## Evidence carried to reuse decision

- **Extend upstream:** viable only if upstream confirms Xenon's session, ownership, target, and acceptance requirements fit Lavish's declared scope.
- **Complementary skill/adapter:** best-supported current seam; Lavish can own one-file review while Xenon owns cross-artifact session, agent entitlement, acceptance, and orchestration. Pin and contract-test documented surfaces.
- **Selective reuse/fork:** copyright-permitted with notices, but internal coupling and rapid churn create ongoing merge, security, browser, and license-audit burden.
- **Standalone:** justified only if Xenon's distinct domain/trust contracts or measured operation outweigh duplicating Lavish's mature recovery, isolation, attachment, mobile, and diagnostic work.

XL-002 selects no posture. Later decision requires upstream scope confirmation, Pi and second-harness black-box tests, hostile-artifact checks, exact reuse inventory, and controlled same-task benchmarks.
