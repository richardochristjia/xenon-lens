# Establish browser isolation and local transport constraints

Primary-source findings: [Browser isolation and local transport constraints](../../research/browser-security.md)

## Answer

**Verified standards facts:** script-capable artifact can run in sandboxed iframe with `allow-scripts` but no `allow-same-origin`, producing opaque origin. Trusted parent then cannot inspect child DOM/selection/state; in-frame bridge using `postMessage`/`MessageChannel` is required. Sandbox does not block network by itself, so server CSP must also constrain connections, forms, frames, objects, navigation, and asset sources. Loopback is potentially trustworthy but not authenticated; runtime still needs loopback-only bind, Host/Origin checks, scoped unguessable capability, request validation, and durable state.

Trust split:

- trusted parent owns queue, explicit Send, persistence, delivery/processing status, responses, and Acceptance;
- opaque artifact frame renders/runs artifact, finds/highlights targets, serializes selected text, and exports only explicit bounded state;
- all frame messages are untrusted context. Frame-visible load secret detects stale/cross-frame messages but cannot prove human intent or honest artifact data.

Selected-text annotation is feasible for MVP using source revision, stable enclosing Target ID, exact quote, bounded prefix/suffix, and DOM offsets as same-revision fallback. Ambiguous/missing match after revision becomes stale; never silently re-target.

Arbitrary application state cannot be captured reliably. Lens-native artifact may expose versioned structured-cloneable export/import hooks; failure must not lose feedback. Parent/runtime preserves unsent queue across iframe reload.

Core UI and runtime should share one canonical loopback origin. Artifact gets no direct persistence/agent credential and default CSP denies network. Exact CSP/asset packaging and one-time bootstrap credential remain later architecture decisions and require Chrome/Edge/Firefox combination smoke tests.
